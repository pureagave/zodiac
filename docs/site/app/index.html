:app · the cockpit

:app — the cockpit

Package org.pureagave.zodiac.control. Kotlin + Jetpack Compose, minSdk 28, targetSdk / compileSdk 35, screenOrientation="fullUser" so each concept reflows for landscape or portrait. This is what the fleet of tablets runs.

Three concepts, one state

Picked with the top-right pill, persisted across launches. Switching is purely presentational — all three read the same state.

  • MotionTrackerScreen

    RADAR

    The Aliens M41A motion tracker. A circular scope whose sweep arm (one revolution every 4 s) lights up the real BRC map as it passes, with art and camp contacts pulsing behind it.

  • InstrumentBayScreen

    MAP

    The Alien Nostromo instrument bay. Bordered tiles: heading dial, speed gauge, ground-track map, cell and throttle gauges.

  • DriverNightScreen

    DRIVER

    A mostly-black OLED night HUD for the driver's phone. Thermal contacts as hollow wireframe figures in a forward perspective view, plus a nose-up surround ring carrying every contact all the way around the vehicle, plus minimal nav.

What is built

Map and navigation

  • Black Rock City rendered from the bundled 2026 Innovate GIS — trash fence, streets, plazas, city blocks, toilets, CPNs. Active year is one source of truth (GoldenSpike.ACTIVE = Y2026).
  • Two map modes: TOP (orthographic, ego centred) and TILT (pitched 3D over a retro perspective grid). Drag to pan, pinch to zoom, two-finger twist to rotate. Heading and speed come from the GPS fix, never from tapping the map.
  • Drive-to: HOME, MAN, TEMPLE, BATH (nearest toilet, re-resolved live), or ADDR — type any city address on a full-screen keypad.
  • Street-following routing with every corner snapped to a real vertex of the GIS street polylines, so the drawn route lies on the drawn streets instead of cutting through camps.
  • Street-crossing popups and “passing” callouts for notable art within 120 m.

Sensing

  • Five pluggable GPS sources behind one interface — FAKE, SYSTEM, BLE, USB, NET. NET is the shipped fleet path and is verified end to end against the real beacon.
  • Automatic NET → SYSTEM failover on a device that has its own GNSS.
  • NET also parses the beacon's five proprietary sensor channels; $ZENV ambient lux drives automatic screen dimming.
  • Threat contacts from the Jetson over ZTHREAT, with an explicit feed state — LIVE / DEMO / ABSENT.

Displays and operations

  • Passenger display: a self-running card carousel for riders.
  • OLED burn-in mitigation: whole-UI pixel shift, brightness breathe and idle dim, and a four-phase idle escalation. Detail →
  • Kiosk mode: device-owner lock task, lockscreen and automatic OS updates disabled. Provisioning →
  • On-device postmortem logging that counts everything it discards.
  • Playa discovery: offline-first cache of the Burning Man API's art and camp records.
  • Pre-rendered art imagery baked into the APK in the cockpit's phosphor treatment.

What is not built

Every vehicle transport is fake

FakeTransportAdapter is the only implementation of TransportAdapter in the repository, and FakeTelemetryRepository the only production TelemetryRepository. The transport chips, CONNECT / DISCONNECT buttons, SetHeading / SetSpeed commands and the thermal / mode / link readouts they feed are scaffolding for a vehicle bus that does not exist yet. Real vehicle data reaches the app only through NetworkLocationSource (NMEA) and NetworkThreatSource (ZTHREAT).

Also not real
  • Two MAP tiles render hard-coded literals: the cell gauges (CELL A 70%, CELL B 45%) and the throttle trace. They are not wired to anything.
  • CockpitUiState.tiltDeg is persisted and clamped but the renderer applies a compile-time 45° instead — a runtime rotationX would not render in that graphicsLayer on the S9+.
  • No automated coverage of the map touch interaction (drag / pinch / twist).

The colour system

A strict semantic palette, set 2026-07-04, shared by all three concepts (ui/concepts/ConceptTheme). This site's own chrome follows it.

ColourHexMeans
Phosphor green#00FF66All chrome — controls, borders, labels
Status blue#00BFFFStatus only — link / GPS state, “this is selected”
Data purple#C77DFFLive data values — headings, speeds, clock, needles, ego marker
Dim green#2C8A4ADe-emphasised secondary text
Alert red#FF5555Faults and extreme warnings only

Amber is banned. The DRIVER concept overrides these with its own dimmer night set (#009E4A / #00421E / #B874E0 / #FF4848) for dark adaptation. The ban reaches the hardware too: zdeck rejects the moving head's amber colour-wheel slots at config construction, not merely by convention.
