# Audit — 2026-08-13 (Fable + Opus fan-out bug hunt)

Eight subagents, read-only, each in an isolated git worktree, each scoped to one
high-risk area from the 2026-08-13 Fable risk survey. Four **Fable** agents hunted
areas 1–4; four high-reasoning **Opus** agents took 5–8. Every finding was traced
in source and, where feasible, **demonstrated with a throwaway experiment** (all
scratch work discarded; the jetson suite baseline was 432 green and `:app`/`:beacon`
suites green throughout). No production code was changed by this pass — it is a
find-and-report catalogue for triage.

**Legend.** Severity `P0..P3` = consequence-on-the-playa × likelihood.
`CONFIRMED` = demonstrated (test/experiment/exact trace); `SUSPECTED` = reasoned
but not run. **LIVE** = active on the fleet today; **LATENT** = correct today,
activates when a named thing changes (a camera is bolted on, `--dmx ola` is
enabled, a second network appears, a lifecycle call is added).

Totals: **~40 findings** — **8 P1** (all CONFIRMED), ~12 P2, ~20 P3 — plus **4
"tests that cannot fail"** and a set of **refuted worries** (things the audit
tried hard to break and could not).

## Area 3 — Collision-flag chain (`jetson/zvision/detector.py`, `geometry.py`, `normalize.py`)

- **P1 · CONFIRMED · `detector.py:171` + `geometry.py:168-169,134`** — the collision
  flag **clears at the closest range**. `bbox_height_to_size` clamps to 1.0 at
  `near_h`; `CollisionEstimator` requires `(size - prev) > 0` strictly, so once the
  size proxy saturates, `closing` is False and the flag turns **off while the person
  is still approaching**. Measured (1.5 m/s approach, deployed config): last flag at
  ~1.0 m, dark inside. **Calibrating `near_h` downward for range resolution makes the
  blind band bigger (~2.3 m at 0.6).** BRAKE keys on this per-frame, no latch. Fix:
  compute "closing" on unclamped `h_norm` (or treat saturated size as non-decreasing).
- **P1 · CONFIRMED · `detector.py:175-179`** — one missed blob erases the track id
  **and** the collision baseline (`_tracks = seen`; `_collision.forget(gone)`), and
  `CollisionEstimator` returns False on first sighting. Measured: 1-in-10 dropout =
  2 dark frames/dropout; **1-on/1-off detection never flags at all** (six fresh ids,
  zero flags); 2-on/1-off flags 1 frame in 3. Critical contrast: a camera `None`-read
  at the same position **preserves** id + flag because the early return at
  `detector.py:139` skips the prune — so the machinery already tolerates gaps; only
  the eager prune destroys state. Fix: a 1–2 frame prune grace (Jetson-side state
  only, no new ids while unseen, no tablet coasting) — pure logic, testable now.
- **P2 · CONFIRMED (arith) / SUSPECTED (field magnitude) · `geometry.py:167` +
  `detector.py:56`** — the az-rate gate is sub-pixel-strict: 1 px of centroid motion
  = 0.8° = **8.0°/s** at 10 Hz vs a 3.0°/s threshold → tolerates only 0.38 px/frame,
  and `boundingRect` centroids move in 0.5 px steps, so a single-pixel MOG2 edge
  flicker kills the flag that frame. Compounding: the Lepton is 9 fps polled at 10 Hz
  (`capture.py:99`), so ~1 frame in 10 is a duplicate → `closing` False → guaranteed
  blink. Fix: compute az-rate/closing over a ~0.5 s window per track.
- **P2 · CONFIRMED · `normalize.py:123-131`** — greedy association is
  contour-order-dependent: two people stepping the same direction can have their ids
  swapped/stolen depending on `cv2.findContours` order, teleporting a bearing (→ flag
  suppressed) and re-minting an id (2 frames to re-arm). Precondition: per-frame step
  > half the track spacing. Fix: assign globally-nearest pairs (sort all
  (blob,track) distances, greedy over the sorted list) — same O(n²), order-independent.
- **P2 · SUSPECTED (design gap) · `geometry.py:145-169`** — **no own-yaw term.** The
  CBDR rule runs on vehicle-relative bearing with no gyro/heading input; any turn at
  10–20°/s sweeps every contact's relative bearing past the 3°/s gate, so the
  collision channel is **structurally dark exactly while the driver is steering**
  (and under washboard vibration). `$GPHDT` exists on the bus but is unused. At
  minimum, document in `DETECTOR.md`.
- **P3 · CONFIRMED (LATENT) · `detector.py:109` + `geometry.py:114`** — `fov_ref`
  defaults to `FOV_HORIZONTAL` in two constructors while the deployed default is
  `FOV_DIAGONAL` (the DOC-1 measured bug). Today's only caller passes explicitly, so
  nothing is mis-aimed, but the next direct construction re-introduces the 1.25×
  bearing stretch. Also `bbox_to_rel_az` has **zero production callers** (~5 tests
  certify a wrapper the pipeline never runs — the `select_best` shape).
- **P3 · SUSPECTED · `geometry.py:156-169`** — two sightings (0.2 s) suffice to alarm;
  consistent with the overnight run's 10 phantom flags in 104 frames. FP direction. A
  min-consecutive-intervals (~3) requirement would also harden bugs above.
- **Checked sound:** `wrap180`; `pixel_to_bearing` (all four lens models, ±64°
  diagonal-ref, NaN guards); `CollisionEstimator` edges (out-of-order/dup-t keep
  baseline, boundaries inclusive); `assign_track_id` wrap machinery (never mints 0 or
  a live id); `to_global`/`merge_contacts` (a collision contact can never be deduped
  away by a non-collision one); `MultiDetector` isolation; `ReBaselineGuard`; `app.py`
  monotonic `t`. NOTE (not a bug, for the tuning session): with default
  `far_h/near_h/min_size` the earliest flag on a walking approach is ~3 m (~0.6 s at
  5 m/s) — those three numbers *are* the warning distance.
